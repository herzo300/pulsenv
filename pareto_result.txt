1. **Локальный кэш‑прокси + префетчинг тайлов**  
   - **Эффект** 10/10 – мгновенная отдача тайлов, устраняет фризы.  
   - **Усилие** S – запустить VPS с Nginx, настроить reverse‑proxy к OSM/Carto.  
   - **Архитектура**:  
     - *z/x/y* (TMS) формат, gzip+brotli.  
     - *prefetch‑зоны* – при первом прокручивании +N/-N слоёв, ленивый «наземный» кэш в SharedPreferences.  
     - Межпроцессный cache (SQLite) для длительного хранения и очистки LRU.  

2. **Оптимизация 3D‑двойника**  
   - **Эффект** 9/10 – одна загрузка в памяти, SW обновление без дёрков.  
   - **Усилие** M – преобразовать GeoJSON в binary Indexed Mesh (ещё 1 MB), добавить LOD‑схемы.  
   - **Архитектура**:  
     - загрузка при старте в фоновом Isolate, store в `ObjectBox`;  
     - отложенная выгрузка из памяти через LRU.  

3. **Кинематографичное визуальное воздействие погоды**  
   - **Эффект** 8/10 – «wow‑фактор» с низкой нагрузкой.  
   - **Усилие** S – скрипт для динамичной анимации через `CustomPainter`/`AnimationController`.  
   - **Факторы**:  
     - Particle‑система 3‑дой разрежённый спрайт‑сет (≈200 частиц/сек).  
     - Всполохи + атмосферные блики с 2‑сглаживанием, без шейдерных дорогих дорог.  
     - Плавное плавление, передача облаков через `ImageFiltered`.  

4. **Сокращение APK и удаление WebViews**  
   - **Эффект** 7/10 – быстрый старт, меньше качек.  
   - **Усилие** M – заменить WebView на `flutter_inappwebview` только для навигации, выносить тяжёлые скрипты в серверный API, собрать Android App Bundle (AAB) с разлейками ABI.  

5. **Оптимизация цепочки загрузок погоды (3 URL‑fallback)**  
   - **Эффект** 6/10 – ускорена первичная загрузка, уменьшено пропущенных запросов.  
   - **Усилие** S – объединить запросы в один агрегированный endpoint через бэкенд‑мост, кешировать на 30 мин, использовать `cached_network_image` для fallback‑снимков.  

Эти пять задач покрывают ~80 % общей боли при 20 % усилий.
